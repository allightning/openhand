# 任务卡 · 机制核六班（活对手：一敌多谱 + 血线换势）

2026-11-14 主窗派发。依据：Notion 待拍 46（用户已拍：①②先行）。开工令：统筹把当前工作区提交后再动。独占 `src/game/sim.ts`。

## 口径

用户的「活对手」体感三来源：每局不一样、战斗有弧、对我有反应。本班做前两件的机制核。变化必须可读——通过情报字段与架势条呈现，不做隐藏数值。

## 阶段

### P1 一敌多谱
精英与座前每个敌 ID 备 2-3 套配招变体（同原型不同侧重，或跨原型：莽夫谱/龟谱/游走谱）。变体表进数据（新文件 `src/game/content/foeVariants.ts` 或并入 `foeArchetype.ts`，按架构归属判断）。按局种子随一套；馆 1-3 杂兵不做变体（仍只莽夫乌龟底座）。情报钩：变体 id 写上 `run` 或敌 kit 的可读字段（如 `foeVariant`），供风声级情报与壳层读取——「他这局带的哪套」必须能被 L0 买到，本班只留字段，情报购买结算不动。

### P2 血线换势
敌 HP 首次跌破阈值（默认 50%，`climbCaps` 标黄 `CLIMB_STANCE_SHIFT_HP`）时，换配招/原型：当前意图队列作废，按新谱重排；架势条按新谱重算（聚合构成当场变）。每场每敌最多换一次。龟→莽为典型，变体表可指定换势目标谱，缺省按原型对照表（莽→莽不变、龟→莽、游走→莽、刺客→刺客、教头→教头）。播报留占位键 `foeStanceShift`，文案由剧情窗供。换势不进虚招规则；反应窗概率按换后原型。

### P3 黄金与验收
变体与换势进黄金帧则逐条写原因。`npm run test:combat` + `npm run typecheck:combat` 全绿。定向测试：变体按种子确定、馆 1-3 无变体、血线一次只换一次、换后架势构成变、换势不重置换势。
