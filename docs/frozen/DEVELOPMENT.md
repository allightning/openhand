## 一、这是一款什么游戏

**明手**是武侠江湖题材的 **2D 探索 + 肉鸽策略卡牌对战**。

| 层 | 参考 | 实际做法 |
|----|------|----------|
| 大地图 | 《江湖风云录》 | 单格贴图、水墨、迷雾、区块小地图、NPC 对话与解谜 |
| 对战 | 杀戮尖塔的**框**，不是玩法 | **7 格石台** + **公开意图** + **组合算招**，不是纯比数值 |

世界观口吻：港律、名册、劲力、卸力、先机。三名被除名的铸战师，从不同入口进入同一张天下图，最终对上谋逆/夺玺。

**产品优先级**：核心循环是战斗。地图只要整洁可读。不要把精力砸在岸线/悬崖抛光上。

## 三、对战（核心）

### 3.1 常数

| 项 | 值 | 文件 |
|----|----|------|

### 3.2 数据流

```
makeBattle() → playCard() / previewCard() → endTurn() → 敌方意图
     ↑ sim.ts                         preview 必须与 play 一致（有测试）
content.ts 数据    party.ts 牌谱    weapons.ts 兵器修正
```

热文件：`sim.ts`（引擎）、`content.ts`（牌/敌/技法/章）、`rewards.ts`（战后三选一）、`bag.ts`（消耗品）。

旧文档写「120 具名兵器」——当前代码是 **60** 个名字。

### 3.4 组合状态（局内，胜负主要在这里）

| 状态 | 作用 |
|------|------|
| 连势 combo | 叠层，连环收 |
| 气脉 flow | 本场攻击 +N，封顶 3 |
| 铺势 setup | 给收势掌爆发 |
| 点穴 mark + 开缝 rift | 印层 → 爆发 |
| 尾劲 echoNext | 下回第一击加成 |
| 铁布 retain | 开局保底格挡 |
| 埋招 riposte | 反击 |
| 裂创/破绽/滞手/反震 | bleed / expose / frail / thorns |
| 禁技/封囊/削谱/扣劲 | 封行动/背包/手牌/内力 |
| 封脉/滞步/乱步 等 | 对玩家的控制 |

`strikeDamage` = 基础 + 下击 + 气脉 + 印 + 破绽 + 连势 等。  
先机（pace）决定谁先动手。

### 3.5 兵器六系

`palm` `saber` `spear` `sword` `staff` `hook`，各两路（a/b），品阶凡/良/精/玄/神。  
牌谱绑定武器：错系进 `scrolls`，等对应同伴入队再教。通用牌标「通用」。

### 3.6 难度

闲步 / 港律 / 死战（`settings.ts` + `system/difficulty.ts`）。  
闲步：敌血约 ×0.52；死战：敌血约 ×1.72。局外难度最多改 3 次、10 分钟冷却。

### 3.7 对战哲学（红线）

- **约 30% 局外容错 / 70% 局内算招**。技法不能碾战斗。
- 难度靠机制与组合，**不要堆血堆伤**。
- 战败：约 10% 血原地复活；连败 3 次本局归档。
- 已共识未做：对手读玩家 buff 改招；战斗 UI 两侧状态栏；换人对位引导。

## 七、UI 与工程结构

`src/main.ts` 是单体壳：地图、对话、战斗、上栏任务、存档。  
`src/style.css`：水墨、石台、对话条、浮动地名。  
`src/fx.ts` 粒子；`src/audio.ts` 音效；`src/art/` 牌面/武器 SVG。

```
src/
  main.ts style.css fx.ts audio.ts
  game/     战斗、局、同伴、任务、中盘
  map/      场景、洛阳生成、准入、渲染
  art/      程序化美术
  assets/   sprite 注册
  data/     洛阳对白库
  story/    未接线主线骨架
  reward/   曲线
  system/   难度
public/art/  PNG：tiles / objs / sprites / stand / maps
```

运行：

```bash
npm install
npm run dev      # http://127.0.0.1:5175/
npm test
npx tsc --noEmit
```

## 八、开发者目标与明确不要

### 想做成

1. 策略深度来自算招，乱出牌应打不赢。
2. 局外养成只容错。
3. 大世界可探索：跨房间解谜、自然遇敌，不是打 3 个 NPC 换图。
4. 故事有链：问 A 得去问 B。
5. 视觉：水墨、单格、抠图走动；不要 STS 框 + 立绘硬贴在地图上。
6. 体量：三线都要够长（设计目标含击败多名要人）。

### 不要

推箱子；墙上写规则说明书；永久数值膨胀；纯堆血难度；改好的地方乱改回去；AI 擅自 commit/push；专门的失败复盘系统。

### 沟通习惯

中文。先讨论后动手。用户会截图红圈。满意的平面/墙/地标不要动。任务文字要短。可作战 NPC 名用红。未要求不要 git commit。

## 九、不可回归红线（跨系统）

**对战**：30/70；技法=容错；10% 复活 / 三死归档。  
**地图**：门户间距 ≥3；水不过细流；门是建筑且有名；旅行门横向。  
**洛阳**：见 `MAP_DESIGN.md` 错误库 12 条 + `LUOYANG_BASELINE.md`。  
**美术**：sprite ≠ stand。  
**文案**：diegetic，线索要链式。

「大总结 / 大评估」若用户没说「地图」，指的是**可玩内容**：谜题、支线、同伴、兵器、敌人、卡牌、buff、连招、钩子、银两——要有数量和短评。
