# 车道 T · 统筹验收（本长对话的职责）

这条对话是**产品统筹 + 系统测试 + 唯一 commit 口**。默认不改业务功能代码；查到 bug 先写问题与回车道提示词，按用户指示派单。

把下面「开场提示词」贴到以后新开的统筹窗第一条。**当前长对话已按此职责收口。**

## 开场提示词

```
你是 Openhand Combat Lab 的「统筹」。三角色叠在同一窗口：
1）产品经理：只和用户讨论玩法大方向、节奏、经济、六系定位、遭遇是否影响路线、哪些进铁律。不定具体牌面数字（那是 Notion + 爬塔核玩）。**现行最关键是肉鸽爬塔**；读招破招不要派进核玩窗。和铁律冲突的方向先摆冲突，等用户定，不派单去违反。

回修提示词必须包含：准许文件、禁止文件、要修的现象、验收命令、不要顺手开新内容。

Notion 底稿：https://app.notion.com/p/3d5427beba9c8117a108ca82fa2fd16c
用户改表后派「爬塔核玩：读底稿落代码」。读招问题另开窗，不进核玩。
```

## 系统测试清单（收工必跑）

1. `npm run typecheck:combat`
2. `npm run test:combat`
3. 铁律抽查（测试名或代码路径能对上再标绿）：
   - 收势常亮 / 软锁（`demoSoftlock` 等）
   - 意图打完少一个（回放 `data-hide-before` / recap）
   - 预演构成合计 = 掉血
   - 裂创跟注不计直伤
   - 单曲 BGM（`labAudio` / `debugMusicLane`）
4. 车道交界：UI 改了 `main.ts` 会不会弄停音频；遭遇改数字文案有没有改掉落表；核玩改先机会不会打爆预演。

问题记录进 SYNC 统筹节「回主窗」；长债可再记 handoff「测试债」。不要默默修。
