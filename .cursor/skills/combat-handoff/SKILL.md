# 踢馆对话交接

## 目标

旧窗把**现行事实**写进文件；新窗只读文件上手。不要靠「还记得上次吗」。

## 何时该交接（满足任一条就做）

1. **话题切了**：设计拍板结束 → 要落代码；或核玩改完要派 UI/遭遇。
2. **一块可验收的活做完**：Notion 一页理清、一包测试绿、一条收件箱已交付。
3. **对话变重**：同一窗已跨多个大主题，或开始复述/漏铁律/漏 SYNC。
4. **闲置将超过 3～4 天**：收工写 SYNC；下次新开或先说「读 SYNC 再开工」。
5. **用户说「交接 / 收工 / 新开窗」**：立刻执行，不要再拖一轮。

**不必交接：** 同主题连着改同一页、同一测试包，上下文仍清楚。

## 交接时写什么（分工）

| 写哪 | 写什么 | 不要写 |
|---|---|---|
| `.cursor/lanes/SYNC.md` | 更新时间；本班状态；需要别窗跟的收件箱一句；「所有人必须知道」只改**改了的那几条** | 长日记、聊天复述、整页机制粘贴 |
| `.cursor/handoff.md` 文首 | 可选 3～6 行：做了什么、未决一句、下一步 | 当现行板 |
| Notion / `RULES.md` | 机制真源若变了，先改真源再提 SYNC | 只改对话不改真源 |
| 车道 `*.md` 开场提示词 | 文件集或禁改列表变了才改 | 每次交接重写整份 |

## 交接输出（给用户）

用这个短模板（可直接粘贴）：

```markdown
## 交接 · [车道名] · [日期]

**已落文件：** （SYNC / Notion 哪几页 / RULES 否）
**现行一句：** （下一窗必须知道的状态，≤2 句）
**未决：** （要用户拍的，没有写「无」）
**下一步：** （下一窗第一件事）

### 新窗第一条（整段复制）
（若是既有车道：指向 `.cursor/lanes/N-xxx.md` 开场提示词，并加上下面「本班续作」一段）
（若是跨切派活：写出完整可粘贴开场，含读哪些文件、准许/禁止、不要做什么）
```

### 本班续作段（接在车道开场提示词后面）

```
本班续作：先读 SYNC 更新行与本车道收件箱。现行：[一句]。下一步：[一件具体事]。未决：[无 / …]。不要重开已锁的骨架/六系核副，除非用户点名。
```

## 新窗冷启动顺序（每个 Agent 自己做）

1. `docs/combat/AGENT.md`
2. `.cursor/lanes/SYNC.md`（含本车道节）
3. `.cursor/rules/combat-ironclad.mdc`（若本窗会改规则或写文案）
4. 需要历史再翻 `.cursor/handoff.md` 文首几条
5. 机制细节：Notion 定稿先后 → 对应合同页；代码对照 `RULES.md`

不要从旧聊天记录猜现行规则。

## 用户侧最小动作

1. 旧窗说「交接」或 Agent 主动按上面触发收工  
2. 新开对话 → 粘贴「新窗第一条」  
3. 旧窗可关可留，但**不要**在旧窗继续改同一主题

## 反模式

- 只在对话里交代、不改 SYNC  
- 把整份 Notion / 铁律贴进交接词  
- 新窗不读 SYNC 就开工  
- handoff 日记当现行板  
- 一次交接塞三个无关下一步
